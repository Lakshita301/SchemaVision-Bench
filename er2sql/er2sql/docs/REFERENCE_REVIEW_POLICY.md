### Authoritative schema

The authoritative schema is the structural/relational end state of the original
scraped source DDL after every source `ALTER` statement has been applied in
source order. The ER diagram is not ground truth (Tier 2/3 intentionally hide
information), and model outputs or PostgreSQL conveniences must never define
the reference. The source SQL files remain immutable.

### Policy-approved translations

The following recurring, explicitly reviewed categories are approved as
meaning-preserving translations, with no per-file signature required:

- Remove integer display widths (for example, `INT(11)` to `INT`).
- Translate auto-increment/sequence spelling to
  `GENERATED BY DEFAULT AS IDENTITY`, preserving explicit inserts.
- Map `VARCHAR2` to `VARCHAR`; declared `NUMBER(p[,s])` to `NUMERIC(p[,s])`;
  bare or wildcard-precision `NUMBER` to unconstrained `NUMERIC`; `CLOB` and
  long-text variants to `TEXT`; `NVARCHAR2`/`NVARCHAR` to `VARCHAR`; binary
  large-object/variable binary types to `BYTEA`; `DOUBLE` to `DOUBLE PRECISION`;
  `TINYINT` to `SMALLINT`; `MEDIUMINT` to `INTEGER`; and `DATETIME` to
  `TIMESTAMP`.
- Move literal column/table comments to PostgreSQL `COMMENT ON` statements;
  convert ordinary indexes and named unique indexes to equivalent PostgreSQL
  indexes/unique constraints (index names are not scored, column sets are).
- Remove physical engine/charset/encoding options and relocate unchanged
  foreign keys after table definitions when required for forward/cyclic refs.
- Remove trailing commas and quote reserved bare identifiers as required.
- Fold backtick/bracket-quoted identifiers to unquoted lowercase PostgreSQL
  names. Quote only when required by syntax/reserved words or when folding
  would collide with a distinct identifier in the same schema.

A changed candidate with only these approved changes, no blockers, successful
PostgreSQL execution, and all generated reference checks passing is approved by
policy. Its audit record must say `policy-approved: <category>; protocol v3
decision log` and retain source/candidate hashes. This is category-level
approval, not a claim of individual human file review.

### Blocker rulings

- Widen unsigned integer types to the next larger signed PostgreSQL type with
  equal-or-greater capacity (`TINYINT UNSIGNED` → `SMALLINT`, `SMALLINT UNSIGNED`
  → `INTEGER`, `INT UNSIGNED` → `BIGINT`). Do not synthesize a nonnegative
  `CHECK`; unsignedness is out of scope for constraint-level grading.
- Convert `ENUM` to `TEXT`/`VARCHAR` with a `CHECK` containing exactly the
  declared values. Exclude `SET` domains as not mechanically equivalent.
- Convert `BINARY(n)`/`VARBINARY(n)` to `BYTEA`, dropping length/padding
  behavior, which is out of scope for this benchmark.
- Drop collations; retain `DEFAULT CURRENT_TIMESTAMP`; drop only
  `ON UPDATE CURRENT_TIMESTAMP` and document that behavior as out of scope.
- Map `DOUBLE(p,s)` to `DOUBLE PRECISION`; floating-point rounding is out of
  scope for this benchmark.
- Exclude schemas whose FK targets a source column that is not declared
  `PRIMARY KEY` or `UNIQUE`; never add uniqueness to force compilation.
- Fix the converter to apply supported `ALTER TABLE ADD/DROP` operations to
  the accumulated schema state in source order, and strip `#` inline comments
  before column parsing. Any residual unresolved operation is documented and
  excluded individually, not guessed.
- Exclude conflicting duplicate table definitions when source provenance
  cannot establish the final definition.
- Fix unresolved constraint drops by tracking explicit and generated
  constraint identifiers. Exclude any residual ambiguous drops individually.
- For comment-mangled sources, strip `#` comments and rerun parsing; exclude
  only those still genuinely malformed/non-standard.
- For `MATCH`, `NULLS NOT DISTINCT`, or `EXCLUDE` currently flagged by the
  static parser, run the existing PostgreSQL DDL executor. If DDL and all
  generated tests pass, approve as-is; otherwise exclude and document.
- Exclude `schema_0924_372982`: the source is SQLite's internal `sqlite_stat1`
  statistics metadata, not an application schema.

When a reference cannot be represented under these rulings, exclude and
document it before model evaluation; never silently alter declared meaning to
make it compile. Remaining genuine one-off judgments need a named reviewer,
source/candidate hashes, and a short semantic note. The reported corpus size is
the exact number surviving the gates after applying this policy—not the
original nominal count.

## Why automatic conversion alone is insufficient

Some failures are dialect syntax, but others are incomplete or contradictory source data:

- `schema_0517`: references `status_type`, whose definition is absent locally. The exact enum declaration has now been recovered from its pinned upstream source; conversion to unrestricted text is unnecessary and would remove the recovered domain restriction.
- `schema_1052_673818`: `empty_types` declares columns with no data types; other columns use ambiguous `INT(precision,scale)` syntax. Inferring types would invent ground truth.
- `schema_1211_489168`: repeats tables `t1` and `t2`; one `t2` definition has ON DELETE SET NULL, another ON UPDATE CASCADE. Selecting one or merging them changes the target schema.

The reports also expose unsupported constraint predicates and fixture limitations. A reference that compiles is not necessarily a valid oracle: all planned tests must pass and warnings must be resolved.

## Recommended decision sequence

1. Record missing definitions and source provenance, but do not promote recovered upstream definitions into the active reference without an explicit decision. Keep the existing dataset authoritative.
2. Agree on the evaluated semantics: a reviewed PostgreSQL rendering of each source schema, with documented treatment of source-specific types, collations, defaults, unsigned ranges, uniqueness, referential actions and deferred constraints. Do not describe this as complete cross-dialect equivalence without evidence.
3. Resolve duplicate/contradictory variants using source provenance and the actual ER diagram, rather than choosing the version that makes tests pass.
4. If a schema cannot be resolved, explicitly approve a benchmark eligibility/exclusion policy before any model outputs are collected. Log each exclusion and regenerate a versioned split. Do not silently use only the currently passing schemas.
5. Review converted references separately from model predictions. Do not use Module 2's predicted IR or Module 3/6 output to construct the oracle.

## Auditable override workflow

Use a separate reviewed-reference directory containing `SCHEMA_ID.sql` files for every ID in the audited split. Original-byte-identical files need no conversion review record. Changed files require a JSON review record keyed by schema ID:

```json
{
  "schema_XXXX": {
    "source_sha256": "SHA256 of original source bytes",
    "reference_sha256": "SHA256 of reviewed PostgreSQL file bytes",
    "reviewer": "Actual reviewer identity",
    "notes": "Source provenance, exact conversions, retained constraints and unresolved limitations"
  }
}
```

These fields document an actual review; filling them is not a substitute for checking semantics. The audit and launch gate compare both hashes. A changed or deleted reference invalidates the evidence. The gate also checks exact schema coverage and identical SQL inputs across models/tiers.

```powershell
python -m er2sql.module7_evaluation.readiness --manifest config/experiment.paper-pilot-v2.yaml --output docs/audits/pilot_oracle.json --reference-dir <reviewed-directory> --review-file <review-records.json> --quiet
```

Use the final manifest and `docs/audits/final_oracle.json` for final-set validation. `--resume` reuses only unchanged records from the exact same plan; source/config changes require a fresh audit. Audits checkpoint every ten schemas, record per-schema errors without abandoning the rest, and return a failing gate for partial or unsuccessful results. Neither audit constructs an LLM client.
